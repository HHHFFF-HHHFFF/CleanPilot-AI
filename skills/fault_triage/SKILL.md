# 故障分级诊断 Skill

## 目标

将扫地机器人异常问题按照安全优先、信息确认、知识核验、逐步排查和转人工判断的顺序处理，避免跳步诊断或给出危险拆机建议。

## 执行流程

1. 从用户描述中提取故障现象、报警码、发生阶段和已尝试操作。
2. 调用 `get_current_device` 获取当前用户绑定的设备型号、设备编号、购买日期和保修期限；身份由服务端运行上下文强制绑定。
3. 若出现冒烟、焦味、异常发热、电池鼓包、严重进水或漏电风险，立即建议停止使用、断开电源并联系官方售后，不继续常规排查。
4. 缺少决定性信息时，优先提出少量关键澄清问题，不猜测设备状态。
5. 调用 `rag_summarize` 检索与设备型号、故障现象和报警码对应的资料。
6. 仅在温湿度或环境可能影响故障时，调用 `get_user_location` 和 `get_weather`。
7. 将排查步骤按“无需拆机、风险较低、用户可执行”的顺序排列，每一步说明操作方式和预期现象。
8. 结合保修期限明确停止排查并转人工的条件，包括安全风险、重复失败、硬件损坏或需要拆机。

## 工具边界

- 允许：`get_current_device`、`rag_summarize`、`get_user_location`、`get_weather`。
- `get_current_device` 的用户 ID 必须以运行上下文为准，禁止查询或披露其他用户设备。
- 禁止查询用户个人使用记录，禁止指导拆机维修，禁止承诺维修结果。

## 输出要求

- 使用“故障判断、建议排查、安全与转人工条件”的清晰结构。
- 区分已确认事实、知识库依据和可能原因。
- 资料不足时明确说明不确定性，不编造错误码含义或设备参数。
